# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity and honest scope | Read the plan's scope pair, implementation approach, test plan, and `## Deviations`; compare them with every changed file/hunk in the diff and with the PR description's claims. | Pass when the diff implements the plan's stated issue and boundary, with no extra behavior or file silently added and no planned deliverable silently omitted. A deviation passes only when the plan's deviation note records it and the PR description states it accurately. The description must not claim exact fidelity when the diff disagrees. | required |
| Decisive test evidence | Read the plan's test plan and reproduction steps, the PR's before/after test-evidence section, and the named commands/output; also inspect the repo's required checks in repo facts and their outcomes. | Pass when evidence exercises the plan's actual failure path and shows an observable before/after or other decisive expected result, and the repository checks named by its standards were run with outcomes visible. Judge the recorded action and result against the issue and plan; do not invent a mismatch from a shorthand test name or label when the package itself explicitly identifies the trigger and shows the expected before/after behavior. “Tests pass,” a version banner, an unchanged control path, or a check with no command/result is insufficient. An honestly disclosed deferred path passes when the plan and description both scope and explain the limitation. | required |
| Diff is reviewable and focused | Read the unified diff, changed-file list, and commit list against the plan and issue. | Pass when the intended fix is easy to inspect and the diff has no unrelated files, debug prints, dead code, commented-out experiments, TODO debris, accidental formatting/reindent churn, or noisy cleanup that obscures the fix. A necessary mechanical change is acceptable when the plan or description explains it and the hunk remains reviewable. | required |
| Repository standards and template satisfied | Read repo-facts PR-template asks, contribution policy, issue/maintainer direction, and the candidate PR description including checklist and disclosure sections. | Pass when every required template section has concrete content, the issue is linked using the requested form, maintainer direction is engaged, required tests/docs/changelog asks are addressed, and any repository AI-use policy is met. If policy requires AI disclosure, the description contains an explicit truthful disclosure; if policy is silent, no disclosure is invented as a requirement. | required |
| Description and title are evidence-accurate | Read the title and description side by side with the plan, diff, and the literal commands/results in the test-evidence section. | Pass when the title names the actual bounded change, the description's scope and factual claims match the diff and the recorded evidence, and it avoids unsupported guarantees, claims of tests or docs that the package does not show, or generalizations beyond the tested setup. Do not make this check fail merely because another check disputes an interpretation of the test trigger; only a direct contradiction or absent claimed evidence fails it. | required |

## Verdict rule

Accept only when every required check passes. A required `unclear` counts as a failure
because a PR that cannot be verified is not ready to submit. There are no preferred
checks; any failed or unclear required check yields `reject`.
